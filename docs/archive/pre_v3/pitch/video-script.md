# TATHYON Prototype Walkthrough (3–4 Minutes)

**Keep the `SYNTHETIC DEMO` banner visible throughout.** This walkthrough demonstrates local software behavior only. It does not show real facilities, live Gemini, a live Google map, government integration, an approved transfer, or measured health impact.

## 0:00–0:25 — State the prototype boundary

**Show:** Home screen with the demo banner.

**Say:** “TATHYON is a prototype for evidence-backed resolution of health-resource record exceptions. Everything in this walkthrough is synthetic. No government system or live facility data is connected, and no transfer is being executed.”

## 0:25–0:55 — Trust Queue

**Show:** Queue and model/provenance notice.

**Say:** “The queue is a deterministic demo ranking, not a validated real-data model. It is intended to help explore how a limited verification budget might be organized. A real pilot would require an authorized source export and independent human counts.”

## 0:55–1:25 — Report intake and anomaly review

**Show:** Submit a synthetic resource report, then the statistical advisory card.

**Say:** “This prototype compares an observation with like-for-like prior observations and can abstain when history is insufficient. Its robust-deviation threshold is deterministic; it is not an AI model, a p-value, or proof of cause. The card is a review cue only and does not change verified state or train a model.”

## 1:25–1:55 — Map

**Show:** Map and synchronized list/table. Keep synthetic label visible.

**Say:** “The map uses base geography with generated example facilities, states, and route illustrations. Routes are not road-routed, approved, or executable. Google Maps is an optional provider but has not been verified in this environment; 45-degree tilt is perspective tilt, not a dedicated 3D map.”

## 1:55–2:30 — Allocation and approval example

**Show:** Synthetic proposal and human-review screen, without presenting an action as executed.

**Say:** “This fixed scenario demonstrates proposal and review states. It is not a recommendation for a real facility and nothing moves. A live deployment would need authorized availability, validated geography, a responsible approver, and department-specific procedures.”

## 2:30–3:00 — Audit and model status

**Show:** Event log and model status.

**Say:** “The local prototype records events in process memory. A hash chain can make changes detectable in this run, but that is not durable production storage or an external signature. The current real-data ledger file was generated by a local simulation; its generated labels are not field attestations, so real-data model training remains blocked.”

## 3:00–3:30 — Validation ask

**Show:** Pilot workflow diagram.

**Say:** “The next step is not a larger model. We need one authorized design partner, a permitted export, a small independent-count campaign, and a shadow-mode test measuring data coverage, verification yield against a same-budget random baseline, and time to close an exception. We will publish what fails as well as what works.”
